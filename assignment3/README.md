# DSO202 — Assignment 3

## Brief

> Utilize the concepts and knowledge gained from the Unit 4 lectures to
> effectively implement Assignment 2 using package and configuration
> management tools like Kustomize and Helm.

Kustomize and Helm are Unit IV in the original syllabus and Unit III (3.2
Helm, Kustomize) in the resequenced descriptor. The brief's "Unit 4" is read
as that material: *01-kustomize-concepts*, *02-patches-and-generators*,
*03-kind-hands-on-lab* and *Unit III 3.2 — Helm*.

The Assignment 2 Task Tracker (PostgreSQL StatefulSet, Ingress with TLS,
per-workload ServiceAccounts, deployer RBAC, probes) is packaged twice, so
that the two tools can be compared on the same application:

| | Kustomize (`kustomize/`) | Helm (`helm/`) |
|---|---|---|
| Model | plain YAML base + overlays that patch it | a chart of templates + values |
| Environments | `overlays/dev`, `overlays/prod` | `environments/dev.yaml`, `environments/prod.yaml` |
| Namespaces | `dso202-a3-dev`, `dso202-a3-prod` | `dso202-a3-helm-dev`, `dso202-a3-helm-prod` |
| Hosts | `tasktracker-{dev,prod}.localhost` | `tasktracker-helm-{dev,prod}.localhost` |
| Config rollout | `configMapGenerator` hash suffix | `checksum/config` and `checksum/secret` annotations |
| DB password | literal in `secretGenerator` (classroom value) | random on first install, kept on upgrade (`lookup`) |
| TLS Secret | `assignment2/scripts/make-tls-secret.sh` | generated by the chart (`genSelfSignedCert`), kept on upgrade |
| Validation | `kubectl kustomize`, server dry-run | `values.schema.json`, a template `fail` guard, `helm lint`, `helm test` |
| Lifecycle | `kubectl apply -k` / `delete -k` | releases with revisions: install, upgrade, rollback, uninstall |

The overlays and environment files make the same environment decisions in
both tools:

| | dev | prod |
|---|---|---|
| frontend / backend replicas | 1 / 1 | 3 / 3 |
| backend resources | base | 100m/128Mi → 500m/256Mi |
| database resources / volume | base / 1Gi | 250m/256Mi → 1/512Mi / **5Gi** |
| DB volume on delete | **deleted** (dev data is disposable) | **retained** |
| PodDisruptionBudgets | none (1 replica could never be evicted) | `minAvailable: 2` for frontend and backend |

## Deploying

Prerequisites: the images are loaded into kind, the ingress-nginx
controller is running, and the host proxy is up (all from Assignment 2).

```bash
export MSYS_NO_PATHCONV=1
cd assignment3

# --- Kustomize ---
for env in dev prod; do
  kubectl apply -k kustomize/overlays/$env
  ../assignment2/scripts/make-tls-secret.sh dso202-a3-$env tasktracker-$env.localhost
done
kubectl -n dso202-a3-prod rollout status deployment/backend

# --- Helm ---
for env in dev prod; do
  helm upgrade --install tasktracker-$env helm/tasktracker \
    -f helm/environments/$env.yaml \
    -n dso202-a3-helm-$env --create-namespace --wait --timeout 10m
  helm test tasktracker-$env -n dso202-a3-helm-$env
done

# --- Use ---
curl -sk https://tasktracker-prod.localhost:8443/api/status
curl -sk https://tasktracker-helm-prod.localhost:8443/api/status
```

## Cleanup

```bash
kubectl delete -k kustomize/overlays/dev
kubectl delete -k kustomize/overlays/prod        # namespace deletion also removes the retained PVC
helm uninstall tasktracker-dev  -n dso202-a3-helm-dev
helm uninstall tasktracker-prod -n dso202-a3-helm-prod
# helm uninstall leaves the namespaces and the StatefulSet's PVCs; remove them explicitly:
kubectl delete namespace dso202-a3-helm-dev dso202-a3-helm-prod
```
